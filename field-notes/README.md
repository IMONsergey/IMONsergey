# Field Notes

Practical notes on building AI-assisted products, design systems, and production workflows that remain reviewable, secure, and operationally credible.

These are not project showcases. They document the engineering principles I use when high-context creative and technical work has to survive real constraints.

| Note | Focus |
|---|---|
| [Evidence Before Output](./evidence-before-output.md) | Provenance, state, verification, and responsible claims in AI systems |
| [Design Fidelity Is an Engineering Discipline](./design-fidelity-is-engineering.md) | Turning visual intent into measurable implementation work |
| [The Prototype-to-Production Boundary](./prototype-to-production.md) | What a prototype proves, what production must prove, and how to cross the gap |
| [Visual QA as Release Engineering](./visual-qa-as-release-engineering.md) | Browser evidence, responsive behavior, interaction states, and release confidence |
| [Private by Design](./private-by-design.md) | Safe automation around credentials, personal data, infrastructure, and client context |
| [Platform-Native First](./platform-native-first.md) | Choosing when to automate inside a platform, export it, or rebuild outside it |

---

The notes are intentionally vendor-aware but vendor-independent in their conclusions. The objective is a durable operating model, not a collection of tool tips.
